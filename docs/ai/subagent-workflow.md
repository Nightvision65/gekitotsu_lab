# 子代理测阵协作

本页维护代理分工、交接和效率核算；生成与评测顺序按[研究流程](formation-tuning.md)，证据按[实验契约](05-experiment-contract.md)。先查[公共工具](../../tools/ai/recipes/README.md)，不另建搜索驱动或缓存。具体阵码、成绩、耗时和会话用量留本地实验。

## 何时值得分工

在用户或适用AGENTS/skill明确要求委派的范围内，默认主代理执行短命令、后台评测、verify与公共状态维护，按需启用一位研究子代理。适合委派的是边界清楚、需要独立阅读较多材料的问题：原阵机制与代表局、已核验批次的父阵增失分、一个来源链或反例。没有独立问题时保持单代理。

不要每个候选、chunk或命令启动新代理。引擎单批只需数秒时，代理启动、重复阅读和交接可能超过模拟时间；直接用现有监督器后台运行。需要持续管理多个冻结步骤、且主代理有独立研究时，才把整段运行交给一位执行子代理，保持到本段验收结束。深读代理可在同任务同版本下复用，后续只补新证据和差异。

独立任务在工具支持时使用`fork_turns="none"`，发送[短任务包](../../tools/ai/recipes/templates/agent-task.md)。它不继承聊天历史，但仍有基础指令、项目约定与必要阅读成本；任务依赖无法可靠外化的对话细节时才继承历史。默认沿用当前模型配置，不擅自切换模型或推理等级，不递归派生。

[OpenAI官方说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)指出独立上下文和短摘要有助于减少主线程噪声、并行独立工作，同时子代理会增加模型与工具调用的token。这里的目标是减少重复阅读和主线程长期携带的细节；总消耗是否减少须实测。

## 写入与资源边界

- 主代理是rules、STATE、LEARNING、最终名单与公共文档的唯一发布者。子代理写自己的独占目录，主代理核验后合并；共享工作区没有自动文件隔离。
- 每个SQLite及raw父目录同一时刻只有一位写者。执行任务明确指定store/out/监督日志目录、线程、批量和真实超时；研究代理只读已发布结果。不让多个代理同时用全线程引擎争抢机器。
- 明确授权的诊断使用独立SQLite父目录、独立out和少量线程。基础/详细结果先匹配评测身份、胜负、HP与结束帧，之后才支持因果解释。raw留文件，用有界query或detail_slice取问题窗口。
- 执行者只完成冻结计划，不自行生成下一批、扩池、改权、换后端或解除STOP。输入、范围或身份改变时由主代理另建计划和输出。

## 依赖与并行窗口

| 正在执行 | 同时可研究 | 继续门槛 |
|---|---|---|
| 原阵三池评测 | 解码后的全部单位知识、结构和时序；已verify池的分群与代表局 | 三池verify及BASELINE全部齐备才生成 |
| 冻结候选评测 | 以前完整核验批次的得失与反例；无反馈依赖的知识问题 | 当前批verify与真实父阵研究完成后冻结依赖反馈的下一批 |
| 稳定态去重与验收 | 只读复核冻结规则与预期检查程序 | 去重verify、来源映射、批量验收齐备才评测 |

生成→统一去重→本轮预期/规则验收→冻结实际码→评测→verify→反馈研究是一条依赖链，代理数量不改变顺序。可读progress报告状态，不能用在跑的不完整成绩选型。两个批次确实无依赖时也要提前冻结这一点。

来源原码有静态位移时保留只读基线，稳定态是独立新码。若用稳定态作微调父阵，可同批纳入“原码→稳定态控制”与“稳定态控制→角度变体”，分别记录真实parentCode、精确改动与完整成绩。控制不继承原码成绩，自动位移收益不归给单角度。该设计仍须先完成原码BASELINE。

## 交接与验收

任务包只给一个问题、阶段、权威输入/哈希、必要阅读入口、允许写入路径、禁止动作、资源预算和完成条件。设计/生成者仍须读基础机制、本轮rules/STATE、全部实际单位及核心/墙/辅助/加速知识；短包不能免除硬约束。只做摘要交接复核时无需重读无关单位。

深读任务同时约定代表对手数、额外模拟、关键帧窗、查询和墙钟预算。达到预算仍不能解释的链条标不确定、保存缺项；主代理只为影响下一步选择的问题追加补证。先读summary和目标统计，再查事件窗口，避免把一个局部假设扩成全场来源普查。

执行者用`experiment step`保存命令/PID/日志/真实超时，发布progress/summary、results与verification哈希、计数、缓存及实际新增模拟。研究者先用`pool_report`的真实父阵比较、分群和变化索引，只选少量改善/退步共同对手。交接约600中文字：结论与支持/否定/不确定、证据路径/哈希、反例、未完成、下一步；详细分析落独占报告。主代理只回读影响决策的证据。

已冻结且没有研究决策依赖的“评测→verify→报告”可在一次工具调用内顺序执行，各步仍有独立step目录、真实超时，退出失败、progress未完整或verify不通过立即停止。无需每个确定性命令往返模型一次；不能把有反馈依赖的下一轮搜索也串进去。

采用交接前检查：

1. 冻结名单、完整固定N、progress为complete、E=0、独立verify通过，结果哈希一致。`evaluate_pool`遇STOP/time-limit可能退出0，`step`成功不等于阵池完成。
2. 引擎/JAR/DLL、侧位、帧、seed、池文件匹配。摘要复核不代替raw核验，不证明未检查的引擎实体。
3. 新阵有生成、统一去重及verify、全部来源映射、本轮预期与规则逐条件验收；完整真实父阵证据存在，不能凭名字或总分猜父阵。
4. 研究保留损失、反例与未测边界；依赖反馈的计划尚未执行，主代理更新STATE/LEARNING后才发布下一步。

失败或超时先独立查PID、progress与日志，复用同身份完整证据补缺；不盲重跑、不读半写raw、不自动恢复用户STOP。只读建议不能当成已执行结果。所有写入停止后再按公共snapshot/verify-snapshot归档。

## 怎样确认效率

记录分配到主代理验收的端到端墙钟，以及命令耗时、代理持续时间、等待/交接和真实新增局数。用UTC区间交集记录实际重叠，重叠量不能直接称为端到端加速；没有同质量单代理对照时不报加速倍数。模拟很短而阅读很长时，优先隔离深读、减少命令往返。

本地JSONL有`token_count`时，用[agent_usage.py](../../tools/ai/recipes/agent_usage.py)对明确指定的主/子会话取快照。分别合计总输入、其中缓存输入、非缓存输入、输出；推理输出已含于输出。累计输入包含多轮重复上下文，不是当前窗口长度，缓存token也不是免费token。工具不输出提示正文，不自动扫描其他聊天。

```powershell
conda activate opencode
python tools/ai/recipes/agent_usage.py --session <主会话.jsonl> --session <子会话.jsonl> --out local-maintenance/<试验>/usage-before.json
python tools/ai/recipes/agent_usage.py --session <主会话.jsonl> --session <子会话.jsonl> --baseline local-maintenance/<试验>/usage-before.json --out local-maintenance/<试验>/usage-after.json
```

前后快照须同一session集合，新增代理另列，禁止重复计入；仅覆盖末次已发布用量事件。无实际计数时标不可测，文件字节/报告字数只作体量代理。

比较历史继承时，同一冻结证据、同问题、同输出与验收要求各做fresh和fork，核验答案一致性，再读会话累计计数。单次结果只说明这两个任务的差异，不外推整个造阵流程节省比例。比较单代理与协作还要计入派发、回读、重试、所有子代理成本与缓存顺序偏差；不要为计时重跑同身份对局。
