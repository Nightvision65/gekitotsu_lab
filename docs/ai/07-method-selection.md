# 造阵方法选型

目标为提高候选对固定标准200阵集的得分率。本文件给出方法选择建议；尚未完成各搜索算法在本项目中的同预算对照，不能把建议写成已经证明的优劣。

## 推荐路线

**在明确授权的方法对照研究中，比较多个起点的程序搜索与LLM结构建议，由冻结模拟器真实评判。** 常规造阵仍从本任务原码或STATE父阵开始，按现行原阵研究和分阶段流程执行；多起点、种群及局部拆除重建是待比较的方法，不自动扩大当前任务。

这条路线无需先训练神经网络。现有Kit和外部脚本已经能完成合法输入审计、批量对战和结果汇总；候选生成、去重与批评测已有[工具入口](09-repeatable-workflow.md)，自动搜索调度和算法对照仍需按具体研究计划验证。LLM目前最合适的输入是解码后的单位列表与对战摘要，输出是受约束的编辑计划，而不是凭字符外观直接改base61字符串。

## 各方案的适用性

| 方案 | 当前判断 | 主要价值与限制 |
|---|---|---|
| 从零训练专用生成器或强化学习策略 | 暂缓 | 要同时解决表示、动作空间、预算约束、反馈、探索和训练稳定性；当前只有一个固定主目标，训练成本尚无理由优于直接搜索 |
| 模仿现有阵码训练生成模型 | 可作以后初始化工具 | 能学常见结构，不直接保证胜率超过训练阵；几百条历史阵不等于丰富的高质量优化轨迹 |
| LLM逐轮调整已有阵 | 适合诊断和小规模探索 | 能提出组合变化、解释源码机制；每个坐标点都调用模型会消耗时间与调用预算，且仍必须实战验证 |
| LLM直接从空白生成阵 | 少量探索分支 | 可以提供结构新意，但合法性、单位协同和精细时序都没有胜率保证 |
| 程序搜索已有阵的坐标、角度、顺序和组成 | 首个应建立的基线 | 不用训练，容易审计和复现；只做单点微调会卡在平台或局部最优 |
| 程序搜索加LLM结构建议 | 优先验证的最终组合 | 程序承担大规模精调，LLM帮助提出更大改动；LLM是否带来净收益仍需对照实验 |

“从空白构造阵”和“从零训练模型”是两件不同的事。可以用规则、模板、随机合法构造和进化搜索产生新阵，不需要先训练一个神经网络。

## 为什么这个项目更适合先搜索

现有输入可直接解码为有限长度的单位列表，包括类型、坐标、角度和顺序。结构的好坏又能通过现有模拟器获得明确结果，因此可以把任务写成“在规则约束内寻找使200阵胜率更高的单位配置”。

阵型组成和顺序是离散变量，模拟器没有可直接用于梯度下降的胜率梯度。按当前U计半分的固定200局主得分最小变化是0.25个百分点，许多微调会持平，也可能在跨过某个接触/出手阈值后突然改变胜负。仅凭文字推理或平滑数值拟合都难以代替实际对战。

看似合理的微调可能在完整阵池上毫无收益；以真实父阵和精确改动做条件对照，不能用机制解释代替实际得分，也不能从一次持平否定整个局部搜索方向。

如果将来要面对大量不同规则、预算和新对手集，训练一个能跨任务快速提出好阵的策略，才更有机会摊薄训练成本。神经组合优化研究确实展示过强化学习生成组合解，但其具体实验问题不是激突造阵，不能直接据此推断本项目效果。[Bello等人的原始论文](https://arxiv.org/abs/1611.09940)。

## 建议的搜索结构

### 多个起点

从用户已有阵中选择约5–10个不同流派作为首轮起点；数量只是起步建议。这只适用于明确授权多起点的方法研究；常规任务从用户本次原码或STATE父阵开始，先完成[原阵三池研究](formation-tuning.md#11-开搜前先充分研究原阵)，不自行扩成多阵任务。不要只保留最高分的一种结构：当前略弱的流派，可能有更大的可改进空间。

保留若干相互不同的候选分支，例如按加速等级、突击方式或对手胜负分布分组，每组保留高分阵。不要一开始建立巨大高维网格。保留多种高质量解的思想与MAP-Elites一致，但具体分组和容量需要本地试验。[MAP-Elites原始论文](https://arxiv.org/abs/1504.04909)。

### 大部分候选由程序生成

先实现少量可靠操作：

1. 单个或成组单位的坐标与角度微调；同组相对位置可保持不变。
2. 交换相邻单位、调整治疗/修复或兵玉与突击壁的先后，核心固定在第一槽。
3. 删除少量单位后，在释放的预算内替换、补充或重新布置。
4. 在明确功能组之间迁移结构，如一个突击组及其配套，而非任意交换阵码片段。
5. 用模板或受约束随机构造产生少量新结构，加入已有种群比较。

第三项相当于“保留大部分阵，拆掉局部后重建”。大邻域搜索的原始思路也是从已有解中移除相关部分，再重新插入；这里只借鉴方法，不声称车辆路径实验结果能保证造阵收益。[Shaw的LNS论文](https://link.springer.com/chapter/10.1007/3-540-49481-2_30)。

种群的最终冠军保留最好已验证分数；探索分支可以保留有新结构的同分或少量低分候选，避免要求每一步都上涨而无法跨过平台。不要将探索分支的退步阵替换成最终交付阵。

### LLM按批次介入

给模型的是：单位表、成本与剩余预算、几场典型败局、贡献数据、重要接触/受击时刻、本轮新增和丢失的胜局，以及已经尝试过的变更。

让模型输出类似“保持前部突击组不变，拆除后排两个低收益单位，用释放预算测试三种破核配置”的结构计划。再让程序枚举合法替换和坐标参数。模型不需要逐个手写几百条阵码，也不负责凭解释给候选打胜率。

可以先按每轮50–200个程序候选、模型提出少量结构计划的方式运行，具体配比由对照结果调整。搜索停滞时增加结构探索，而不是机械增加同一坐标附近的重复尝试。

“预训练LLM提出候选，自动评估器筛选，再把高分候选反馈给下一轮”在FunSearch中有明确先例。对这里的启发是使用可执行的评估闭环，而非必须复现FunSearch或训练模型；适用于本项目的程度仍须测量。[DeepMind的FunSearch说明](https://deepmind.google/blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/)。

## 评测和资源利用

- 常规造阵以固定200阵、固定侧位与引擎下的[当前得分率](10-benchmark-usage.md#评分与晋级)为迭代主指标；已选基底微调默认以完整2000迭代，最终完整10433决胜。预算、核心和禁限条件先验检查。
- 固定子集只用于诊断；常规造阵新候选完整200，已选基底微调默认直接完整2000、冻结决赛名单后完整10433。阶段与旧的淘汰式小集预筛建议均以现行[阵集政策](10-benchmark-usage.md)为准。
- 同阵码、同对手、同引擎、同侧位、同帧数只评估一次，复用结果。默认确定性下重复对战不能增加样本量。
- 大批候选在一个或少量Java进程中运行；现有示例桥接每次调用会重新编译并创建隔离工作目录，适合批量使用，不适合每一个微调启动一次进程。搜索级结果缓存可以放在实验目录，不需要修改引擎。
- 常规造阵按200计，1000个候选为20万局、同时换边为40万局；微调直接按2000计入实际预算。耗时依据本机批量实测计算，不使用上游机器的games/s承诺时间。
- 主分持平时可以用成本、对局画像或辅助侧位保留不同候选。额外伤害、剩余血量、结束帧只能作辅助，不能盖过当前声明评测池的实际得分率。

固定200目标允许直接围绕该基准搜索。原游戏一致性与其他阵池表现分别报告，不替换用户的主要标准；完整流程的入围与大集决胜按阵集政策执行。

## 如何判断推荐是否真的划算

在投入训练之前，先做一个有计算预算的对照实验。建议比较三组，均从相同的多流派初始阵、相同规则与200阵集出发：

| 组 | 方法 | 检验内容 |
|---|---|---|
| A | 多起点局部搜索，主要改坐标/角度/顺序 | 建立便宜、可靠的基线 |
| B | A加种群保留和局部拆除重建 | 检验跨结构探索是否值得 |
| C | B加LLM结构建议 | 检验模型调用的额外价值 |

首轮可给每组2万局，再用3个不同的**搜索器随机种子**重复，共18万局预算；这些数字是建议，不是已经执行的试验。初始基线、筛选和最终完整200评测都计入预算，模型生成的候选也不能获得额外免费模拟。

记录完整200最佳胜率随已用局数的曲线、达到相同分数的总耗时、合法候选率、LLM调用次数/费用、每个起点的提升与最终结构多样性。三个搜索种子用于观察搜索稳定性，不是在同一确定性阵对上重复抽样。三次重复只是初步判断，不足以宣称方法普遍优越。

若C的提升与B相当，就减少LLM参与；若B没有优于A，先查重建操作是否破坏结构。没有必要为了使用更复杂的算法而保留没有实际收益的步骤。

## 什么时候再训练模型

优先考虑一个较小的候选排序器，学习“哪些修改值得优先拿去真测”，而不是直接生成完整阵。它使用搜索中积累的不同阵型和真实逐对手结果，测试时按阵型家族隔离，防止近似阵泄漏。代理模型只负责排队，最终胜率仍由模拟器确定。

只有当持续获得的独立阵型与对战数据足够、评测已成为主要瓶颈、且要长期适配多种规则/阵集时，再考虑训练编辑策略或构造策略。若做强化学习，动作应是添加/移动/替换/调序等结构操作，加预算和合法性约束；不把生成base61字符本身当作游戏能力。

这套判断的当前优先级为：先验证多起点搜索，再验证结构重建与LLM的增益，最后根据真实瓶颈决定是否训练。它可以逐步升级，每一步都有直接的200阵胜率证据。
