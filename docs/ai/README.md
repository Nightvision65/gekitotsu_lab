# 激突Kit 造阵文档

本工作区使用现有模拟器研究阵型、检验假设并交付有完整对局证据的阵码，同时保存发行包和研究版源码。默认工作目标是造阵；引擎、GUI和插件开发须由具体任务授权。环境与后端身份见[项目地图](01-project-map.md)，协作要求见[AGENTS](../../AGENTS.md)。

## 按问题使用文档

准备搜索时，先用[造阵基础机制](08-formation-fundamentals.md)理解坐标、支撑、更新顺序、保护和恢复如何影响战斗，再按实际解码ID读[单位百科](knowledge/units/README.md)中的共享机制、本阵全部单位与核心。新增兵种或职责时补读；条目缺失、版本变化、矛盾或新问题超出条目时才追源码。火线横移和连续压制需要结合[弹幕时序](13-volley-timing.md)，分清初始计数、触发周期与实际命中。

理解阵型战术时，[战术知识库](knowledge/tactics/README.md)帮助识别获胜路径、体系配合、相性与变体；[防守部署诊断](knowledge/defensive-positioning.md)帮助区分防区位置、墙体承伤和支撑作用。这些专题保留自己的适用条件。具体阵的用户选择、固定参数、反例和停止状态保存在使用者的本地STATE，不把案例参数套到新阵。

决定怎样实验时，[搜索设计](04-search-workflow.md)把观察变成可检验的改动轴和失败判据；[通用搜索经验](11-search-lessons.md)用于设计单项/联合对照、检查边界与平台、解释组合收益并限制结论。[批量实验知识](knowledge/batch-design-dedup-defense.md)补充保序去重、来源映射、职责分组和模块写入字段的检查。[方法选型](07-method-selection.md)用于比较局部搜索、结构重建和模型建议的成本，里面尚未实测的方法建议不改变现行执行要求。

解释战果时，[分析使用](knowledge/analysis-usage.md)说明画像、两类热图、删除贡献和伤害来源各能回答什么，以及样本、寿命和共同时间窗的限制。[数据契约](data-contract.md)给出坐标、side/slot、事件和缓存字段；[详细模式](detailed-mode.md)用于对明确对局追查攻击、HP写点、消弹与对象来源链。诊断后端先查[HP规则版本](unit-hp-rules.md)，避免用修正版源码解释旧DLL对局却省略一致性核验。

## 从准备到交付

| 需要完成的工作 | 使用入口及其职责 |
|---|---|
| 确认整体步骤与工具分工 | [可复用流程入口](09-repeatable-workflow.md)连接研究、生成、审核、评测和交付；[研究执行流程](formation-tuning.md)保存完整操作顺序与后台运行方法 |
| 理解原阵后再开搜 | [原阵研究](formation-tuning.md#11-开搜前先充分研究原阵)要求完成原阵三池、200分群和代表胜败局研究；同配置证据可核验复用 |
| 明确测哪些阵、怎样计分和选拔 | [阵集与评分](10-benchmark-usage.md)维护三池角色、U半分、固定分母、弹性规模、入围和决胜规则 |
| 生成可审计的候选 | [阵码契约](02-formation-format.md)解释base61、坐标和单位顺序；[生成器](generator.md)解释JSON计划、规则、模板、抽样和accept |
| 确认开局稳定且规则合法 | [重力审核](gravity-audit.md)定义静态模型、稳定态转换和侧位限制；预算、禁限、固定字段仍单独检查 |
| 调工具与处理运行问题 | [工具手册](03-tool-runbook.md)提供opencode、UTF-8、代理、构建、桥接与查询示例；[能力地图](capabilities.md)用于选择实际存在的接口 |
| 每批研究后决定下一方向 | [持续候选研究](formation-tuning.md#22-搜索中持续研究候选再决定下一步)对齐真实父阵、逐对手收益/损失、分群和少量详细对照 |
| 在已选后继阵上做小范围微调 | [微调流程](formation-tuning.md#23-已选基底的小范围微调)默认完整2000起步、完整10433收尾，连接基线复用、每组位移边界、支撑职责联动、旧码去重、小联合与最终角度复查 |
| 保存可复现证据与交接 | [实验契约](05-experiment-contract.md)定义冻结身份、记录、实际局数、本地归档与通用知识提交；[STATE模板](templates/STATE.md)承载当前状态 |
| 核对后端和证据适用范围 | [项目地图](01-project-map.md#引擎核验与证据范围)说明构建身份与对照条件；[HP规则](unit-hp-rules.md)说明源码与发行包差异 |

[知识入口](knowledge/README.md)适合按知识问题查阅；[任务提示词](PROMPTS.md)提供简短任务模板。正文按主题维护，入口只说明用途和触发条件。评分定义在10、执行步骤在formation-tuning、记录字段在05、底层字段在data-contract，避免平行复制。

## 使用前的状态核对

先读本任务STATE、rules和明确父阵，保留用户选择与停止状态。当前生成包装器只支持`generate / accept`；新候选使用`gravity.py evaluate`先审后评，再用`verify_pool.py`逐池核验。历史文件中出现的其他包装子命令不代表当前可运行。

阵池身份按[固定文件与清单](10-benchmark-usage.md#阵集角色与身份)核验。文档保留服务造阵的规则、操作、机制和证据边界；发现冲突时有明确先后采用新版，无法判断则直接向用户报告，确认后合并进对应主题，不另留已解决事项的项目历史文档。实验原始输入和证据保留其冻结身份，仅在本地保存；公开文档不依赖维护者的实验目录。
