# 稳定态去重与本轮布局验收

重力处理回答两个问题：草稿最终会站在哪里，哪些草稿其实是同一个稳定布局。初始y相差1px的兵玉可能落到同一平台；按原码逐条评测会重复消耗预算。发生下落或上挤也不直接淘汰，先统一去重，再由本轮预期判断布局是否值得保留。

## 静态模型与证据范围

调用Rust核心实际`Ball::land`，保留实体形状、车板/核心/墙体支撑及坐标量子化，普通兵玉不互相承托。核心先转换到实际世界位置。关闭攻击、治疗、召唤、推进、撞击、突击、升降、旋转及狙击转态，墙体固定初始位置。

当前公共审核实际推进1P，输出`kit-workbench`坐标；不能自动声称2P或完整战斗也满足该几何。收敛要求连续静止且支撑落体速度归零，默认观察240帧、静止窗口12帧；参数须满足`2 <= stable-frames <= max-frames <= 2000`。未收敛末帧、失败或超时都不能冒充稳定态。

## 通用入口

所有Python先激活conda `opencode`；首次运行先构建静态工具。输出目录必须是新目录。

```powershell
python tools/ai/gravity.py build --timeout 240
python tools/ai/recipes/stable_dedup.py run --input experiments/my-run/generated/candidates.json --out experiments/my-run/dedup --timeout 120
python tools/ai/recipes/stable_dedup.py verify --run experiments/my-run/dedup
```

`--input`可重复给出，所有位移通过和未通过的草稿放入同一个任务。相同纯码只计算一次；按`--batch-size`成批调用静态工具。`--exclude-run <既有去重目录>`可重复给出，核验相同工具/模型身份和收敛窗口后排除已声明的历史稳定几何。历史排除范围由本轮计划明确，不能把别轮预期下的拒绝自动套到新任务。

### 去重与代表规则

- 使用核心及全部单位按原slot顺序的类型、稳定x/y和角度，连同静态模型/构建、侧位形成指纹。单位不排序，不按同分合并。
- 坐标编码为引擎0.05px格点的整数刻度；先核对偏差在0.001px浮点容差内，拒绝离格点数据。实际相差1px的布局保持不同。
- 同类优先保留首次位移检查通过的合法原码；否则选首次可编码稳定态新码，并批量重放确认零位移、收敛、回编码幂等及几何一致。几何不可编码时保留首次合法来源原码，位移未通过也不阻止其进入本轮验收。
- 被支撑挤到负y时，负y参与几何指纹，不夹紧或强写非法新码；用合法来源原码表示该稳定布局。
- 原码的`auditPassed`只标记位移情况：允许y=0正常上挤和的玉下落例外。它影响默认代表选择，不直接决定最终搜索资格。

代表只是草稿。全部别名和原始行保留，本轮若有来源相关的固定字段或允许改动范围，可从同类其他来源选择合格表示，不能因默认代表不合格就丢掉整个类。几何去重是搜索取舍，不证明源原码的开局过渡和战斗等价；缓存仍以实际评测纯码为准，新码不继承源成绩。

### 输出与状态

| 文件 | 用途 |
|---|---|
| `manifest.json`、批量request/result | 冻结输入、模型/工具指纹、观察范围及原始静态证据 |
| `input.json`、`results.json` | 全部来源行与按唯一原码计算的结果 |
| `classes.json` | 唯一稳定几何、全部源索引、默认代表及历史重复引用 |
| `aliases.json` | 来源文件/行→simulationIndex→稳定类→草稿索引 |
| `candidates.json` | 待本轮验收草稿，移除旧成绩，保留真实父阵等来源信息 |
| `pending.json` | 未收敛者及原因，不当作最终淘汰 |
| `summary.json`、`REPORT.md` | 位移通过/未通过、唯一原码/布局、历史重复及草稿数量与证据哈希 |

退出码0表示已得到非空、无待查项的去重草稿；3表示存在待查项或没有新草稿，完整分类证据仍保存。`requiresSearchAcceptance=true`始终保留；`verify`只核对去重证据，不批准战术预期。不得悄悄把部分输出当整批完成。

## 本轮搜索预期

预期随任务变化，使用[预期模板](../../tools/ai/recipes/templates/search-expectations.md)冻结本轮条件，并由本轮检查程序批量执行，不要求统一战术判定器。至少说明关注slot、参照阵、约束阶段、位置范围、支撑对象、相对关系、侧位与容差；只检查本轮真正需要的条件，不套用其他阵的槽位或阈值。

检查程序读取稳定类、别名、来源结果和本轮rules，逐条件输出实际值及通过/拒绝/证据不足，并发布最终合法代表名单。预期应在生成前声明，不能看成绩后倒改；未通过原码位移检查的稳定态只要符合预期也可保留。记录要求见[实验契约](05-experiment-contract.md#稳定态去重与搜索预期证据)。

涉及支撑破坏时，实际执行“带支撑稳定→删除实际支撑→继续稳定”，记录前后位置与支撑；需要两侧就分别构造两侧。静态成功不保证受击后全战表现，仍须完整对战检验。

## 工具分工

`gravity.py audit`提供位移诊断；`apply`处理整批可编码稳定态并复核幂等，`verify`核对其源输入及证据。需要这种单独转换时可配合生成器`accept`重验已有规则。搜索候选统一使用本页去重流程，完成本轮验收后再调用[评测与核验](formation-tuning.md#评测与逐池核验)。

静态模型验证见[Rust测试](../../rust/gravity/src/main.rs)、[重力测试](../../tests/test_gravity_gate.py)、[统一去重测试](../../tests/test_stable_dedup.py)及[Java oracle](../../tests/GravityOracle.java)。冻结对手池只读，不转换、不因诊断结果删条目或改变权重。
