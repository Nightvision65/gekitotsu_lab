# 造阵研究与执行流程

本页维护从原阵研究到交付的操作顺序。改动设计见[搜索设计](04-search-workflow.md)，对照与扩圈见[搜索经验](11-search-lessons.md)，阶段、评分和规模见[阵集政策](10-benchmark-usage.md)，证据与归档见[实验契约](05-experiment-contract.md)。

当前工作链为：冻结输入 → 原阵三池研究 → `formation_workflow generate` → `stable_dedup run` → 本轮批量预期/规则验收 → `evaluate_pool` → `verify_pool` → 研究反馈。先查[复用工具与模板](../../tools/ai/recipes/README.md)，使用公共生成、去重、评测、报告与快照入口；具体战术判断和依赖反馈的计划留本轮记录。

## 1 明确输入与允许改动

新任务保留用户名称、原纯码与SHA256；续跑先读STATE和rules，确认父阵、剩余额度、停止状态和已有证据。冻结预算、核心、禁限、顺序、固定字段、配对、侧位、帧上限、种子政策、后端和真实超时。用`experiment.py init --jar <研究JAR>`核验`--ai`入口与JNI并冻结引擎副本，后续评测和诊断显式使用该副本；命令见[建档](../../tools/ai/recipes/README.md#建档与单步运行)。用户硬约束与阶段选择分别记录，不用工具默认值替代任务范围。

搜索/生成前读[基础机制](08-formation-fundamentals.md)、本任务rules和STATE；按实际解码ID读[共享机制及本阵全部单位与核心](knowledge/units/README.md)，覆盖墙、辅助、加速器、生成物及职责依赖。同任务同版本可复用阅读，新增兵种/职责补读；缺项、矛盾、版本变化或超出条目的新问题才追源码并补回知识。横移火线另查[时序](13-volley-timing.md)。目录、工作台与实际战斗状态分别解释，构建核验见[HP规则](unit-hp-rules.md)。

## 1.1 开搜前先充分研究原阵

原阵是用户本次原码或STATE明确起点。先回答如何运转、靠什么赢、为何失守，再生成候选。

1. **结构与机制。** 逐槽说明火力、防护/消弹、支撑、回复、加速、突击职责，检查预算、核心、顺序、初始加速、时序和静态支撑。记录知识来源与待验机制，不从兵种数量直接猜战术。
2. **三池完整基线。** 同一冻结身份下完成或核验复用200、2000、10433，逐池verify，保存原始计数、胜率与哈希；只补同身份缺局。三池完整、E=0且核验通过前不开新候选搜索。阵池身份按[固定版本](10-benchmark-usage.md#阵集角色与身份)，条数不能替代文件哈希。
3. **重点研究200。** 用逐对手结果和元数据，按相关兵种/组合、加速、核心与攻防结构分群，列定义、N、计数与胜率，注明重叠和小样本。工作台、画像、核心热图或等义离线聚合定位优势/弱点，2000/10433核对更广相性，不能只存总分。
4. **解释代表胜败局。** 从主要优势与弱点中选择有问题的胜败局，必要时补D/U、临界局和反例。先读结果、结束帧、可用HP/存活，再按问题复用或补少量基础/详细对战，检查实际出手/命中、消弹、关键单位、核心受创/回复、支撑破坏与突击落点。记录对手索引和配置一致性；后端结果不一致先诊断，不能确认原评测因果。不强制全量遥测或删除贡献。
5. **落盘后开搜。** BASELINE或等价报告包括结构/单位阅读、三池核验、200分群、代表局、获胜手段/失败路径、限制及首批“观察→假设→改动轴→预期改善群→副作用/失败判据”。STATE链接权威报告，分清实测、源码机制和假设，齐备后才标完成。

同任务同配置可复用基线与研究；内部换父阵不机械重跑三池，已有结果继续分析。换起始阵或证据身份变化时补对应基线，续跑只补缺项，不恢复停止任务。

来源原码先做规则与重力诊断。有位移的冻结来源仍可直接用`evaluate_pool.py`完成只读三池诊断，保留原码与位移证据；这不代替新候选去重和预期验收。稳定态新码独立记账、重新评测，不继承成绩，也不例行重复建立三池基线。

## 2 生成、稳定态去重与验收

先以有对照的小批检验机制，有实测收益再扩大联合或密集搜索。[生成器](generator.md)用短JSON计划显式指定base/rules，完成组合、规则拒绝和纯码保序去重；坐标规则固定组成与顺序，结构规则逐阵重算预算与初始加速。

```powershell
conda activate opencode
python tools/ai/formation_workflow.py generate --plan experiments/next/plan.json --out experiments/next/generated
python tools/ai/recipes/stable_dedup.py run --input experiments/next/generated/candidates.json --out experiments/next/dedup --timeout 120
python tools/ai/recipes/stable_dedup.py verify --run experiments/next/dedup
```

生成结果与去重输出均是内部草稿。去重将全部位移通过原阵和未通过阵的稳定态合并，不先淘汰未通过组，保留全部来源。跨批排旧只使用明确声明的同身份`--exclude-run`，不继承别的任务的验收结论。负坐标等几何可用合法来源原码表示；未收敛单列待查。模型、精度及代表策略见[重力审核](gravity-audit.md)。

生成前填写[本轮预期模板](../../tools/ai/recipes/templates/search-expectations.md)，由任务自己的批量检查程序验收唯一类：关注位置、支撑、相对关系及原码/稳定态/拆撑后阶段。对选定代表复核预算、禁限、顺序、固定字段、配对、dropControl和可导入性，逐条件保存accepted/rejected/pending及证据。`formation_rules.check`只有返回`None`才通过；错误字符串也是失败。

原码位移未通过、稳定态符合本轮预期的可以保留。y=0被挤到负y的稳定几何可用合法来源原码表示；不得夹紧几何。默认代表不满足本轮规则时，检查同类其他来源并记录选择；新码须稳定、可编码且幂等。冻结实际代表名单与源阵→几何类→纯码映射后才评测，新码不继承源成绩。

## 评测与逐池核验

按[环境准备](03-tool-runbook.md#环境准备)激活opencode，使用已验收名单。下面示例常规造阵的200阶段；已选基底微调按政策直接从2000开始。可能较长的命令用[step监督器](../../tools/ai/recipes/README.md#建档与单步运行)设置真实总超时。

```powershell
python tools/ai/recipes/experiment.py step --out experiments/next/steps/evaluate-001 --timeout 3600 -- python tools/ai/evaluate_pool.py --jar experiments/next/inputs/engine.jar --candidates experiments/next/accepted.json --opponents experiments/next/inputs/pool-200.txt --side 1 --store experiments/next/cache/store.sqlite --out experiments/next/training --threads 24 --batch-size 64 --timeout 600 --time-limit 3400
python tools/ai/verify_pool.py --run experiments/next/training --candidates experiments/next/accepted.json --opponents experiments/next/inputs/pool-200.txt
```

2000与10433替换冻结名单、opponents和独立out，按工作量调整超时；通常2000每批4阵、10433每批1阵，单批最多64阵且通常不超过12800局。各池独立verify后汇总身份和完成状态。重合对局仅在纯码、对手、物理侧位、引擎/适配器、帧上限、种子一致且原始哈希核验后复用；不同包装指纹不混库，评分变化可重聚合而不重模拟。

默认候选1P。需要2P时实际用`--side 2`，完整同N后按[评分政策](10-benchmark-usage.md#评分与晋级)报告双侧。先按1P筛选再补2P可能漏掉1P稍低而双侧更强的版本；物理侧位和索引解释见[数据契约](data-contract.md)。

## 后台评测与续跑

默认后台非阻塞，保存命令、PID/会话、日志、输出、冻结输入及真实超时；使用可返回会话的方式或`Start-Process -WindowStyle Hidden`。确认启动后继续相关独立研究，不频繁轮询。`--time-limit`只在批间检查，单批`--timeout`与监督器总超时分别设置，工具等待时长不能代替它们；超时先独立查进程、日志和结果再处理。

进度读`progress.json/summary.json`，最终以独立verify为准；raw已落盘而汇总未刷新时，完成数0不表示没有对战。在跑输入和构建冻结，只读已完整发布且核验的结果。新诊断独立目录与SQLite父目录、少量线程，避免共写或挤占主评测；顺序可复用同库，跨库汇总保留raw路径和哈希。

停止在对应out放STOP，于批次边界保存，并处理等待触发的驱动；用户明确续跑才用原命令恢复，不改旧manifest扩池或换候选。在跑不写已完成，用户提问及时回应。

整批未完而指定纯码已有完整证据时，可另建明确名单与独立输出核验作父阵。零新增快照可在新out预置STOP，加载缓存后须`status=complete`、`newGames=0`且verify通过；快照不重复计唯一阵数，原批声明候选仍须完成。

## 2.2 搜索中持续研究候选，再决定下一步

每个有对照批次完整发布并verify后，先研究再冻结依赖其反馈的计划；不要求逐候选或逐chunk写长报告。在跑批次保持原输入。

1. **对齐真实父阵。** 保存父阵与候选的精确slot/字段改动和契约。逐对手比较计分，列改善/退步数、增加/损失/净计分、百分点和完整变化索引；原基底/推荐版另列，不能把不同父阵的差异归于一个字段。
2. **解释受益与受损。** 按相关兵种/组合、加速、核心和结构列组定义、N、前后成绩与净分；组重叠不相加，各池分开。持平也查增失抵消，目标群未改善保留失败预测。
3. **保留有信息的竞争者。** 包括高分、温和变化、不同区域、持平或略低但独特收益的版本，必要时保留反预测方案。模块用同父阵单项/联合对照，不只沿榜首扩圈。
4. **核验关键解释。** 先写预测，从改善/退步各选少量共同对手；没有某类变化如实标无。基础/详细重放先确认输入、后端、胜负、HP与结束帧一致，再查相关窗口的出手/命中、消弹、支撑/火力存活、核心受创/回复和落点来源链。不一致先排错。
5. **决定下一步。** 解释标支持/否定/不确定，记录继续分支、换父阵、补反事实、联合或暂停的依据、目标群与副作用。待验机制只能作小批问题，不能据此密集扩搜。及时更新LEARNING与STATE。

已有结果先离线重聚合。[pool_report](../../tools/ai/recipes/README.md#离线排名分群与父阵比较)提供排名、真实父阵增失分与自定义分群，不新增模拟；它不替代机制研究。画像、热图与贡献的证据边界见[分析使用](knowledge/analysis-usage.md)，按问题补[详细重放](detailed-mode.md)，不能把地面落点一概视为失败。

## 2.3 已选基底的小范围微调

沿用户已选后继阵与明确范围工作，默认完整2000起步和迭代，冻结决赛圈后完整10433收尾；不先用200筛选或强制逐码补200。基底三池研究核验复用、只补缺项；用户限定阶段从其约定，未测范围明示。

1. **冻结目标与边界。** 记录总体目标、关键群、门槛、同分次序、阶段和唯一新码上限。把“小幅”写成slot/字段、方向、绝对参考阵、逐轴或欧氏距离、组内联动和角度圆周差；父阵更新不能累积绕过原边界，联动组不自动重复累计每个实体位移。
2. **画出职责依赖。** 将墙与所撑单位、诱导、治疗、保护、出手位置和顺序写成稳定态预期。联动收益归于完整改动，反事实须实际稳定且符合本轮预期。
3. **生成并验收。** 按前文去重全部稳定态、保留别名与真实父阵，再批量验收。用户要求不重测旧码时，区分排除任意已测码与仅复用当前池完整证据；新表示重新验规则、独立计分。
4. **分离后做小联合。** 首批保留单项、温和变化及必要反向对照，随后做合法F/A/B/AB，默认逐新码完整2000。按2.2比较真实父阵与原基底，略低总分而有独特群收益的分支也保留。
5. **复查耦合与边界。** 平台、防区变化后，在最终几何下联合检查互相保护单位的角度与角差；单项角度成绩不直接迁移。少量共同对手查后续循环而非只看首伤/整局总次数。胜出新点注明是否查过邻圈；无新合法点记录零新增，不为凑额度重跑。
6. **冻结决赛并交付。** 看新增大池成绩前冻结名单与决胜规则，保留总体有力、非支配、温和及独特收益分支。全部入围版完整10433并verify，核验复用同配置基底和重合局，从完整结果另聚合10235。并列迭代池、大池总体/关键群、原始计数、实际新增局数与精确改动，说明取舍，不事后混池改权。小幅改动也不能把迭代排名直接当最终排名。

额度是上限。停止时记录受测邻域与未覆盖联合，不以用满额度或一轮无提升宣称全局收敛。

## 交付与知识归档

交付实际完整的名单与阵池、纯码和改动、原始计数、收益/退步、哈希与限制；原游戏未验标待验，无提升保留基线。停止或未完成只保存现场。完整实验按[归档契约](05-experiment-contract.md#实验完成后的本地归档与知识提交)先保存并核验本地结果，再将可公开机制/方法合并主题，仅本地提交通用知识或工具、不自动推送。具体阵码、成绩、用户选择与证据留本地；共享文档修改前重读，AGENTS最后修改。
