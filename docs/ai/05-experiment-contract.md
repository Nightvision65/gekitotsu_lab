# 实验记录、证据与交接契约

本页定义保存什么和怎样收尾；操作顺序见[研究流程](formation-tuning.md)，评分/阵池/规模见[阵集政策](10-benchmark-usage.md)。一次实验按冻结计划界定，不按每个候选或底层chunk界定。

## 目录与权威状态

每次实验使用新的`experiments/<run-id>/`，不覆盖用户原码、GUI输入或旧评测。`experiments/`及`research/`为Git忽略的本地工作目录，由运行时创建；公开仓库只分发工具、模板和通用知识。下文路径均为使用者创建的示例，不依赖维护者的实验文件。可按实际用途组织：

```text
experiment.json / rules.json       目标、范围、预算、身份与评分
inputs/                           原阵、对手快照或固定路径、来源/标签
baseline/ / BASELINE.md            原阵三池证据、核验与机制研究
candidates/                       计划、候选、精确变更与别名映射
results/                          原始批证据、审计、各池核验与衍生汇总
LEARNING.md                       每批研究、反例与下一步依据
final/selected.txt / report.md     可导入码与结论
STATE.md                          当前阶段、权威交付、未完成项与续跑入口
```

未运行的分析文件不创建。STATE头部始终反映当前阶段和未完成项，历史追加不得让初始状态冒充当前状态。复制[STATE模板](templates/STATE.md)和[实验元数据模板](templates/experiment.json)；后者不是CLI自动消费配置，命令须与之核对。

[实验复用工具](../../tools/ai/recipes/README.md)的`init`核验研究`--ai`入口和JNI后，冻结源输入、规则、阵池与必填JAR并创建模板。引擎记录包含`inputs/engine.jar`、JAR/DLL指纹及`engine-probe.json`，实际评测与诊断显式使用该冻结JAR。`step`记录命令/PID/日志/真实超时；`snapshot/verify-snapshot`核验文件与SQLite引用raw，外部依赖只绑定哈希、不复制，不冒称可搬迁备份。具体结果与盘点留本地。

## 冻结身份与字节一致性

保存原码和纯码SHA256、规则/计划、各池文件与顺序/条数/权重、JAR/DLL或观察器与适配器指纹、物理侧位、帧上限、种子政策、进程超时、搜索器随机种子及实际预算。来源版本、工作台属性和实际战斗构造分别标注。换引擎、规则、阵池或种子政策另建版本；线程调整先小集核验，不当作增加随机样本。

冻结输入、原始结果和证明文件按字节保持SHA256。归档与恢复后重新核对实际文件哈希，记录检查范围；抽查部分文件不能当作全目录逐字节验收。本地证据不加入公开仓库；使用其他私有备份工具时也须避免换行转换改变冻结字节。

## 开搜前原阵研究记录

BASELINE或等价报告与STATE须覆盖下表，缺项仍停留在原阵前置阶段，不能以候选200门禁跳过。详细研究步骤见[原阵研究](formation-tuning.md#11-开搜前先充分研究原阵)。

| 记录项 | 内容 |
|---|---|
| 输入与知识 | 原纯码/哈希、规则/重力审计、单位ID与百科路径、版本、槽位职责、x/y/r影响、配合和待验机制 |
| 三池证据 | 原阵200/2000/10433各自W/L/D/U/E、固定N胜率、verify和来源哈希，区分复用与实际新增模拟 |
| 对手分析 | 重点200的优势/弱势分群定义、N和成绩，Kit工具或离线聚合的实际发现，2000/10433反馈差异 |
| 代表胜败 | 对手索引/哈希、基础结果、问题、必要D/U和反例、诊断后端/HP规则、结果一致性及证据 |
| 首批计划 | 获胜手段、失败路径、事实/机制/假设、不确定性，以及观察→改动轴→目标群→副作用/失败判据 |

有位移的来源原码保存只读诊断及位移审计，该诊断本身不代替新候选验收；其稳定态仍可进入统一去重与本轮预期自动验收。采用稳定态新码时另存纯码/哈希和新评测，不继承成绩。同配置阅读与证据可复用，续跑只补缺项。

## 候选与对手元数据

候选沿用工具字段，不另建同义schema。最终名单须能由以下信息还原实际输入、真实父阵和改动：

```json
{
  "name": "g001-c001",
  "code": "<实际纯码>",
  "sha256": "<纯码SHA256>",
  "parentCode": "<真实父阵纯码>",
  "parentSha256": "<父阵纯码SHA256>",
  "coordinates": "kit-workbench",
  "changes": [{"slot": 7, "field": "x", "before": 118, "after": 119}],
  "hypothesis": "检验落地后的第一轮出手与存活",
  "cost": null,
  "accelLevel": null,
  "legality": "pending"
}
```

占位符替换、成本/加速重算后才发布；计划路径/哈希、搜索随机种子、合法性和阶段可保存在批次证据中关联，不必重复塞入每行。调序保存完整before/after序列或old→new映射，删除后不能用新slot解释旧贡献。名称/路径不作唯一身份，全部别名仍保留；稳定几何与实际评测纯码分开，不据几何合并转移成绩。

### 稳定态去重与搜索预期证据

按[重力流程](gravity-audit.md)记录以下内容，并在STATE同步完成范围。原码位移标记与最终预期验收分列，不能以`auditPassed=false`直接填最终淘汰。

| 记录项 | 最低内容 |
|---|---|
| 冻结搜索预期 | 规则/独立预期文件及哈希、检查程序指纹、参照阵、slot、约束阶段、侧位、坐标系、位置/支撑/相对关系与容差 |
| 稳定态证据 | 源纯码、原码位移检查结果、收敛范围、逐槽初始/稳定坐标、支撑对象、模型及构建身份；未收敛/失败单列 |
| 统一去重 | 输入完整范围、稳定态去重键与数值政策、通过与未通过两组并集、全部别名、等价类与代表选择策略 |
| 自动验收 | 去重后各唯一布局逐条件的实际值、通过/拒绝/证据不足及原因；执行输入与输出哈希，不用逐阵人工查看代替 |
| 发布与计数 | 全部源阵→唯一稳定态→实际评测纯码映射、原码或新码表示、规则与幂等核验；位移通过/未通过、收敛/待查、去重前后及最终保留/拒绝/待查数量 |

统一去重保存`stable_dedup`的input/results/classes/aliases/candidates与summary，绑定原生批报告哈希。本轮预期由任务检查程序批量执行，使用[模板](../../tools/ai/recipes/templates/search-expectations.md)冻结条件；未实现或未执行项如实标明。

对手至少记录`id/name/codeSha256/source/family/tags/pool/weight/ruleset`，冻结池不因候选同码或含U删条目。诊断子集保留原索引；新辅助池的去重、阵族和留出使用状态单列，不替代主池权重。

## 搜索中候选研究记录

每个有对照批次完整核验后，按[持续研究](formation-tuning.md#22-搜索中持续研究候选再决定下一步)及时写LEARNING与STATE，至少关联真实父阵/精确改动、逐对手增失分与完整索引、分群定义/N/前后成绩、预测及代表对照证据、支持/否定/不确定结论、保留分支与下一批依据。程序聚合、模型研究有信息代表，不逐候选写长报告或全开详细模式；后来证据不倒写为先前依据，在跑输入不随反馈改写。

## 原始结果与汇总

逐局证据至少能还原：

```text
run_id, candidate_hash, opponent_hash, candidate_side,
engine_hash, adapter_hash, ruleset_hash, max_frames, seed_policy, explicit_seed,
status, winner_hp, frames, raw_path, raw_sha256, matrix_row
```

低层桥接包含`engine/engineVersion/maxFrames/seedPolicy/p1/p2/forward/reverse`及provenance。Kit JNI不提供显式seed或双方HP/终局RNG，未知写null；`KitLab`记录`engine-default`，研究版批评测记录`native-default`，保留工具原字符串与适配器指纹，不凭语义相近混缓存。详细重放完整结果的可观察范围见[数据契约](data-contract.md)。

单侧标准200应恰好`200*C`，双侧`400*C`，其他池用固定N。保留W/L/D/U/E、胜率、逐对手来源与变化；异常/未完成单列，不吞成负局或平局。汇总CSV可包含候选身份、版本、成本/加速、各池各侧N/W/L/D/U/E/score、对基线差、must_pass、合法性和原游戏状态。每个字段明确单位，Kit贡献delta已是百分点，不再乘100。

低层`kit_lab battle`的单矩阵不提供运行中逐局续存；批运行器按完整chunk/来源缓存恢复，两者不能混称。只复用同身份、原始哈希通过的完整证据，不把半个raw当成功。

## 阶段名单、预算与后台现场

计划保存目标规模、调整理由、候选/必测池与入围/决胜依据。STATE分列原阵前置和[本轮适用阶段](10-benchmark-usage.md#训练竞争验证与决赛)，未入围标未测，不写验证失败；增加名单/阵池另建run，不改冻结manifest。

分开记生成数、唯一纯码数、各池完整候选数、计分局数、跨池唯一对局及实际新增模拟，说明原阵是否计入。重复、控制、诊断、线程核验均按实际计入；失败且无法核算的工作量写未知，不以0替代。已有缓存不重复占名额/局数，不擅自扩大用户上限。

后台记录命令、PID/会话ID、stdout/stderr、输出、真实进程超时、STOP和断点，以及期间研究与下一批假设。只读已发布完整证据，区分完成/在跑；命令超时后先查状态。运行方式见[后台与续跑](formation-tuning.md#后台评测与续跑)。

## 暂停与交接

STATE写当前阶段、权威报告/推荐、冻结输入、剩余预算、失败预测、待完成命令和验证数据使用状态。下一位先核验文件/哈希再接待办，不重跑已有结果或重建整个引擎。停止任务保留STOP，未经用户指示不恢复；未完成实验只保存现场并明确未完成。

## 实验完成后的本地归档与知识提交

完整实验自动执行以下顺序；200搜索、2000验证和10433决赛可按各自冻结计划独立收尾，不要求整项研究全部结束。

1. **本地归档。** 本轮声明评测与适用verify通过后，保存输入、精确变更、原始证据/哈希、成绩、报告和当前STATE。无提升同样归档；缺局、异常或停止不能标实验完成。实验目录、具体阵码、成绩、运行日志和私有案例均保持Git忽略，不强制加入索引，不提交到公开分支。
2. **知识复核。** 归档核验完成后重读相关共享文档，将可由公开源码、规则或完整说明支撑的通用机制与方法整理到对应专题。具体参数、用户选择、成绩和证据路径留在本地记录；公开正文不得链接私有实验或以未分发的附件作为使用前提。待验解释保持为假设。
3. **仅提交公开变更。** 只暂存本轮通用文档或必要工具的改动块，检查暂存清单与引用后使用中文提交说明，不自动推送。没有新增通用结论时，在本地LEARNING或STATE记录原因，无需制造空提交。提交失败保留现场并报告；交付本地归档位置及实际产生的公开提交哈希。

发布时使用不含私有实验历史的分支。`.gitignore`只阻止新文件进入索引，不能清除已有提交中的结果；保留旧历史的本地分支或归档标签不得一起推送。一般文档整理按具体任务授权处理，涉及AGENTS的改动仍放其他文件和验证之后。

## 最终报告要素

交付目标与赛制/暂定条件、可导入纯码及精确变更、成本/核心/加速/数量/审计、各阶段必测池与各侧完整计数/得分、相对基线收益和退步、机制解释及反例、后端/哈希/来源、原游戏核验状态、剩余范围和下一问题。三池取舍按冻结依据解释，不用均分掩盖退步；无提升保留基线，不给持平阵贴“更强”标签。
