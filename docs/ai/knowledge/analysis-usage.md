# Kit分析、空间数据与按需诊断

热图、画像和事件数据分别描述空间关联、对手分群与实际战场行为。基础机制见[单位机制](../08-formation-fundamentals.md)，条件比较见[比较原则](../11-search-lessons.md)。

## 数据类型与含义

| 分析 | 回答的问题 | 解释边界 |
|---|---|---|
| 对手核心位置热图 | 面对哪些核心工作台位置的对手，当前阵得分偏低？ | 已有完整结果与对手元数据可离线关联；不是己方核心平移实验 |
| 兵种、加速、核心类型画像 | 改善了哪些对手群，又损失了哪些群？ | 已有结果可重聚合；组可重叠，相关性不证明败因，单独的循环赛属于另一种样本设计 |
| 己方槽位受创/死亡热图 | 哪个火力、防护或支撑槽位经常受创/被移除？ | 来自战场遥测；不是实际受伤/死亡地点图 |
| 删除贡献 | 哪些单位在当前阵中贡献较低，值得优先调整？删去某单位/组合会怎样？ | 需要对应合法删改阵的真实对局；删除同时改变支撑、治疗、保护和时序，不是普遍单位价值 |
| 基础事件与突击统计 | 什么时候半血、回满、死亡、出击、落地，落在哪里？ | 地刺或带采配突击落地可符合战术，不统一判失败 |
| 详细事件与来源链 | 哪个具体对象何时攻击/造成HP损失，能否追到原单位？ | 依赖对象身份、槽位、时间及来源关系；攻击动作与命中分别解释 |

## 用贡献分析寻找修改方向

贡献分析可用于筛查当前阵中贡献较低的单位，为下一轮改阵提供方向。固定父阵、对手池、引擎与侧位，先看单删结果：删除后得分提高，或只损失少量得分的单位，可列为优先研究对象；结合单位军资与每军资变化，检查其当前投入是否值得保留。

注意字段方向：`delta=删除后胜率-原阵胜率`，正值表示删后更好，接近0表示删后总分变化小，明显负值表示删除损害表现。因此筛查低贡献单位时优先看较高的delta，不能把最负的delta当成贡献最低。

围绕这些单位提出具体对照：调整位置或角度以发挥作用、替换兵种、减少重复配置，或将释放的军资投入其他火力、防护与辅助。结合逐对手改善/退步、支撑关系与单位职责判断，必要时补少量遥测或组合删除；单删贡献低不代表该单位在其他布局或联合配合中也无用。修改后的新候选须通过重力与合法性审核，再完整评测标准200，以实际成绩决定是否采用。

## 两种热图与真实事件地点必须分开

- [CoreHeatmapPanel](../../../src/main/java/org/example/GUI/CoreHeatmapPanel.java)使用对手阵集的核心工作台x/y，将本阵对该对手的结果放到该位置，再做平滑。它不回答“把己方核心搬到这里会更强吗”，也不提供弹丸轨迹。
- [SlotHeatmapPanel](../../../src/main/java/org/example/GUI/SlotHeatmapPanel.java)把槽位累计受创/死亡叠到己方阵型工作台位置。核心不参与该槽位热图统计，核心受伤需另查标量/事件；它不是战场世界坐标中的死亡散点。
- 实际受伤、死亡、攻击或突击落点需要对应事件坐标。工作台坐标与`battle-world`分开；攻击事件x/y通常是生成对象出生点，炮口等偏移不能当单位中心。卡高对应特定早期帧的单位中心位置，终局位置不能代替。

热图与画像的含义依赖阵码、阵池、引擎、物理侧位、样本N、分组边界和平滑参数。稀疏区域的结论较弱；平滑颜色不是新增证据。相同初始化相位或镜像开局不代表双侧等强。

## 统一计分，不照搬旧GUI分母

现存`CoreHeatmapPanel.rebuild`只处理胜/负/平，跳过U和异常。当前按[评分政策](../10-benchmark-usage.md#评分与晋级)将U计半分并纳入样本，E、缺局和程序超时仍拒绝，不能丢弃后缩分母；保留W/L/D/U/E。

按物理侧位解释胜方：status1/2为实际1P/2P获胜；候选在2P时不能继续把status1算候选胜。原始reverse索引已经交换输入，按纯码和双方身份核对。双侧完整性与精确同分按同一评分政策处理，索引映射查[数据契约](../data-contract.md#身份坐标与输入)。

空间画像只帮助提出方向，不因热点重选对手、删耐久局或调整主评分权重。不同池分别报告，历史参与选型或构建验证集的数据不称独立未见测试集。

## 比较受创、死亡和来源时的共同条件

前后阵用相同对手子集、侧位和共同时间窗，时间线标明每箱样本数；先求和再除sampleCount，结束后的缺样本不能当死亡或零输出。累计受伤多可能因为活得更久或回复更多，需并列绝对量、治疗、存活与时长。

按报告metas核验槽位映射，不能把旧GUI非核心index0当阵码核心slot0。`deathFrame`还可能来自要塞毁灭后的统一清理，结合HP与写点区分。伤害占比分母是累计有效HP损失，可以因回复超过初始HP；终局负HP归零不是治疗。

动作多不等于伤害多，对单位HP伤害为0也不能证明没有拦弹。当前攻击者与root来源是同一份伤害的不同视角，不能相加。`entityId`、单位`typeId`和生成对象`kindCode`分开；开壁kindCode34在`shield-as-ability-v2`是ability，旧空查询不能证明没有出壁。旧开壁记录需要时可从objects的ownerUnitId与birthFrame重建区间；详细事件表和字段随schema核对，不凭空筛选报告“零治疗”。

回复阵比较必须排除寿命混杂：新胜局更长、累计损失更多，也可能防守更有效；首次受创帧和早期伤害/恢复都相同，后续交换仍可能翻盘。按共同尚未结束窗口比较，再定位后续分歧，不将首伤延后、伤害更小或恢复总量更多单独作为强度代理。

核心清理时仍有HP的加速器不能解释为HP耗尽变速；核对HP写点、核心毁灭时刻与实际axl变化。恢复事件先核对当前schema枚举（当前详细事件为`heal`），再与`unitStats.healingReceived`及HP账本交叉检查；空筛选不等于零恢复。

删除贡献的小集若多为败局，许多删除都落在计分下界而持平；这不能证明防守件无用，也不足以排出普遍单位价值。对手含某兵种只是筛查线索，指定局实际主要失血可能来自其他单位或碰撞。
