# 贽玉（ID 41）

在车体相撞或撞边时承担牺牲，保护本侧免受该次碰撞扣血与碰撞受击标志；因此驻车壁玉不会仅因该次碰撞受伤、关壁，圣玉也不会仅因该次碰撞重置蓄力。

## 身份与适用范围

| 项目 | 固定值 |
|---|---|
| 编码ID / Rust类型 | 41 / `BallKind::Nie` |
| 军资（工作台目录） | 150 |
| 战斗构造HP | 30 |
| 初始化speed | 0 |

依据Rust提交`149e365221b09330a72d9a6a1804605e3ce4e1f5`与当前`catalog-hp-v1`规则，版本选择见[规则版本](../../unit-hp-rules.md)。本文机制是源码结论；用途与微调建议是基于机制的待测方向，不代表单独胜率证明。军资/中文名来自工作台目录，HP与时序以Rust构造和分支为准。先读[共通规则](common.md)中的兵玉部分；[文档清单](coverage.json)保存单位条目与源码身份。

## 触发与节拍

speed=0；被nie_ball_alarm选中后alarm=6，逐次step_ex倒数至0时把自身HP设0。

speed>0时，普通工作台x的初始cnt为`-((x+16)%speed)`；这里的计时是有效递增次数，跳跃会暂停递增，受伤等可能改变状态。speed=0不套取模公式。

## 详细机制与生成对象

- 两车接触时，base_move先为每侧查找unit列表中第一枚贽玉；找到便跳过该侧碰撞扣核心HP与dokkan_flg设置，但车体反弹速度仍照常改变。
- Base撞边也查找贽玉，存在时跳过边界碰撞扣血和`dokkan_flg`设置；车体仍照常反弹、移动。
- `Ball::step`以`jump_flg==0 && dokkan_flg[on_side]`触发驻车兵玉碰撞受伤。贽阻止本次碰撞置位后，这条扣1HP及调用`hurt`的路径不发生。壁玉因此避免碰撞触发的`shooting=false`及计数重置，圣玉避免碰撞触发的蓄力归零；这是圣贽维持防区和续接的重要机制，不只是核心HP保护。
- 贽不防普通攻击。壁玉仍会因直接攻击受伤、跳跃、自然周期或死亡而收壁；没有贽的复活空窗也仍可能发生碰撞受伤。完整战术链见[圣贽](../tactics/07-holy-sacrifice.md)。
- alarm倒数到0在step_ex末尾设HP0；普通死亡检查在之前，通常下一次step才清理并写dead_last。若在此期间再次被选中，alarm可以重新设6。
- 多贽按unit列表首个匹配选择，不是距离碰撞点最近。圣玉能重建贽玉，但可能被其他死亡覆盖dead_last，须跟踪顺序。

## 受击、恢复与死亡

普通hurt没有额外重置；alarm=0的自我牺牲设HP0，随后通过普通死亡路径处理。治疗在普通死亡检查之后，不能救回已判死者。

本体受击、支撑、跳跃、heal与死亡顺序见[共通规则](common.md)。独立生成物不自动随本体死亡消失；依附物是否清理由各自分支决定。

## 改阵与对手诊断

x/y主要影响存活、支撑及治疗覆盖，r没有主动攻击意义；slot顺序决定多贽优先选择。报警不按距离筛选，不要求贽贴着核心或位于碰撞前沿。观察牺牲、死亡记录、圣玉蓄力和复活出口是否完整衔接，同时核对碰撞时壁玉是否避免受伤、护壁是否继续存在。

发现对方带此单位时，同样检查它的支撑、保护、实际出手位置与生成对象；先选少量目标对局确认机制是否生效，再用完整评测判断改阵收益。
