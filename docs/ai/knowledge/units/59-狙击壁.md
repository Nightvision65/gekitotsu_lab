# 狙击壁（ID 59）

狙击壁，为覆盖兵玉提供逐步朝目标修正的辅助。

## 身份与适用范围

| 项目 | 固定值 |
|---|---|
| 编码ID / Rust类型 | 59 / `WallKind::Snipe` |
| 军资（工作台目录） | 200 |
| 战斗构造HP | 50 |
| 初始化speed | 墙体专用，见触发规则 |

依据Rust提交`149e365221b09330a72d9a6a1804605e3ce4e1f5`与当前`catalog-hp-v1`规则，版本选择见[规则版本](../../unit-hp-rules.md)。本文机制是源码结论；用途与微调建议是基于机制的待测方向，不代表单独胜率证明。军资/中文名来自工作台目录，HP与时序以Rust构造和分支为准。先读[共通规则](common.md)中的墙体部分；[文档清单](coverage.json)保存单位条目与源码身份。

## 触发与节拍

无主动周期；存活时注册snipe传感器，每个被覆盖兵玉在自己的step中判断。

## 详细机制与生成对象

- 覆盖形状就是Wall形状，普通兵玉用(x,y+16)测试；不是以墙为中心的大范围光环。
- 命中后调用Ball::snipe，每次最多向core_x/core_y目标转1°，目标可被敌的玉替代；初始r与有限转速仍影响首次出手。
- 共通辅助链先处理上方跳、前方跳，再处理snipe，再处理转向；重叠不等于全部同时生效。
- HP50，接repair，普通墙breaking；kill移除snipe列表。

## 受击、恢复与死亡

沿用普通墙受创与破损路径；被辅助兵玉的HP/受伤按自己的单位规则。

修理读取Repair，具体破损、立即死亡或动态箱体分支按上文。

## 改阵与对手诊断

x/y同时决定支撑与辅助覆盖；墙自己的r不生效。核对兵玉落稳后的查询点和转向时间，射角微调需考虑战中自动修正。

发现对方带此单位时，同样检查它的支撑、保护、实际出手位置与生成对象；先选少量目标对局确认机制是否生效，再用完整评测判断改阵收益。
