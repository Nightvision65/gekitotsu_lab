# 远突击壁（ID 56）

按计数周期发出前方跳脉冲，提供较远突击与延后出击。

## 身份与适用范围

| 项目 | 固定值 |
|---|---|
| 编码ID / Rust类型 | 56 / `WallKind::Far` |
| 军资（工作台目录） | 50 |
| 战斗构造HP | 35 |
| 初始化speed | 墙体专用，见触发规则 |

依据Rust提交`149e365221b09330a72d9a6a1804605e3ce4e1f5`与当前`catalog-hp-v1`规则，版本选择见[规则版本](../../unit-hp-rules.md)。本文机制是源码结论；用途与微调建议是基于机制的待测方向，不代表单独胜率证明。军资/中文名来自工作台目录，HP与时序以Rust构造和分支为准。先读[共通规则](common.md)中的墙体部分；[文档清单](coverage.json)保存单位条目与源码身份。

## 触发与节拍

墙cnt初值为工作台(x+16)%900（正值），每次+1，到900触发并归零。合法x范围内首次需884-x次。

## 详细机制与生成对象

- 脉冲中心(x,y-35)，接收条件与近突相同，但注册JumpF；普通兵玉设置xs=15-30×on_side、ys=-4并翻转on_side。
- 这是墙的触发时点，不保证附近兵玉在该刻符合jump_flg=0且处于脉冲内；实际起跳与顺序、支撑和落地相关。
- 不能套普通兵玉负cnt公式；同一x下延迟和后续900周期分开。跳跃时普通兵玉攻击cnt不递增。
- HP35，接repair，沿用普通墙breaking与失去车体的清理。

## 受击、恢复与死亡

沿用普通墙路径；墙死亡会失去后续周期，但已生成脉冲按自身更新清理。

修理读取Repair，具体破损、立即死亡或动态箱体分支按上文。

## 改阵与对手诊断

x既改空间也改首次脉冲时间；y改变接收范围与平台关系，r不生效。保留晚出击候选，核对实际落点、再次触发和战斗收益。

发现对方带此单位时，同样检查它的支撑、保护、实际出手位置与生成对象；先选少量目标对局确认机制是否生效，再用完整评测判断改阵收益。
