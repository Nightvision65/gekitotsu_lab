# 界玉（ID 24）

多个有效节点连接成护线，用节点位置与角度组织防区。

## 身份与适用范围

| 项目 | 固定值 |
|---|---|
| 编码ID / Rust类型 | 24 / `BallKind::Kekkai` |
| 军资（工作台目录） | 90 |
| 战斗构造HP | 20 |
| 初始化speed | 0 |

依据Rust提交`149e365221b09330a72d9a6a1804605e3ce4e1f5`与当前`catalog-hp-v1`规则，版本选择见[规则版本](../../unit-hp-rules.md)。本文机制是源码结论；用途与微调建议是基于机制的待测方向，不代表单独胜率证明。军资/中文名来自工作台目录，HP与时序以Rust构造和分支为准。先读[共通规则](common.md)中的兵玉部分；[文档清单](coverage.json)保存单位条目与源码身份。

## 触发与节拍

speed=0；KekkaiField每次更新重建有效节点与线段，无主动发射CD。

speed>0时，普通工作台x的初始cnt为`-((x+16)%speed)`；这里的计时是有效递增次数，跳跃会暂停递增，受伤等可能改变状态。speed=0不套取模公式。

## 详细机制与生成对象

- 有效节点必须存活、jump_flg=0、side=on_side且hurt_time<=0；节点位置为本体+33×方向。
- 按kekkai_ids顺序连接相邻有效节点并闭合首尾；至少2点才有判定。每条线段及端点距离≤15的区域有效，内部不自动填充。
- 受伤设置hurt_time=5并在step_ex递减，暂时退出有效点；死亡移除kekkai_ids。节点删去后其余点按当前顺序重新连线。
- 结界登记Shield；与壁玉一样是弹体/射线等路径中的形状阻挡，不是友军全局减伤。

## 受击、恢复与死亡

任意hurt（含车体碰撞）设置hurt_time=5；死亡除普通清理外还移除结界节点。

本体受击、支撑、跳跃、heal与死亡顺序见[共通规则](common.md)。独立生成物不自动随本体死亡消失；依附物是否清理由各自分支决定。

## 改阵与对手诊断

x/y/r同时改变节点和边，单位顺序也会改变连接。检查受伤后剩余节点、跳跃状态和保护目标；只比较静态多边形面积会漏掉断线。

发现对方带此单位时，同样检查它的支撑、保护、实际出手位置与生成对象；先选少量目标对局确认机制是否生效，再用完整评测判断改阵收益。
