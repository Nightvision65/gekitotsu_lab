# 单位共通规则

本页与当前阵中每类单位页一起阅读；初次改阵先按解码ID查[索引](README.md)，包括核心、墙体、加速器与辅助。对对方感兴趣的单位也按同一ID查阅。无需为了常规改阵再逐一通读源码；出现未收录单位、版本变化、机制冲突或新问题时，再按页尾定位补读对应分支并更新知识。

## 适用引擎与证据层级

机制基础为Rust提交149e365221b09330a72d9a6a1804605e3ce4e1f5，当前另含[本地HP修正catalog-hp-v1](../../unit-hp-rules.md)，当前路径是[rust/vendor/gkt-core](../../../../rust/vendor/gkt-core/src/)，逐文件身份见[source-hashes](../../../../rust/vendor/source-hashes.json)。公开快照不等于对内置DLL全部内部状态的逐帧证明；真实对局必须冻结后端、JAR/DLL、输入、侧位、帧上限与seed政策。每页将源码数值、已有实测和待测用途分开理解。

只为标准200中实际出现的45种非核心单位及2种核心建独立页；生成的弹体、近战区、幽灵、箱体、生物收在其来源单位页。生成物自身的类型与初始阵码单位ID不是一套编号。目录军资/名称只作静态元数据，战斗HP、计时和行为按Rust实际构造核对。

## 兵玉：坐标、计时与移动

普通工作台坐标为x/y：raw=(x+16,y+20)，1P初始战斗位置=(x+66,y+152)，2P=(1854-x,y+152)，2P角度先变为180-r再归一化。核心使用另一套偏移，见[阵码契约](../../02-formation-format.md)。坐标量化为向零截断20v再乘0.05，不会自动吞掉1像素整数变更。

speed>0时两侧普通兵玉的初始cnt都为-((x+16)%speed)。先取模再取负；speed=0不套模0。首次触发阈值不一定等于speed，重置周期、连发内间隔、持续施法与有效命中也不同；具体数值查单位页。普通受伤也不统一重置计时。

land/ground每次递增cnt，jump不递增。land先随on_side车体平移，再以重力1下落，用脚点(x,drop_y+15)查询墙/核心/车体支撑，按1像素上推到不重叠；普通兵玉不能互相堆叠作该项支撑。相邻初始y可能落稳到同一高度，仍可能在落地前出手不同。

jump先加0.32重力再移动，脚点落到当前on_side墙体后回到land，侧向碰墙可令xs=0；落到y566进入ground，横向越界清理。ground兵玉被敌方wall覆盖时会死亡并写dead_last。x移动跨支撑边缘也可能改变y轨迹，初始成组dx/dy不保证战中间距不变。

## 兵玉：辅助、受击与死亡顺序

移动后先检查采配，再按上方跳→前方跳→狙击→逆向转向→顺向转向的if/else-if链处理。跳跃脉冲查询本体中心且要求jump_flg=0；狙击与转向查询(x,y+16)。后续分支可能被前面的分支遮住。side代表阵营，on_side代表当前附着车体，两者不可混用。

随后以中心±8四角查询敌Atk，或按当前状态处理车体碰撞；命中是布尔OR，该次普通受创扣1HP并调用hurt。多枚攻击同一步重叠不自动累加成多倍扣血。然后判HP<=0或所在车体败亡导致的死亡，写最近死亡类型dead_last并移除；之后才处理heal，最后step_ex出手。因此死于本步的普通兵玉不能在这一步回血或发射。

受伤的专用中断规则见[壁玉](19-壁玉.md)、[圣玉](34-圣玉.md)、[迎玉](40-迎玉.md)、[魔玉](06-魔玉.md)、[星玉](51-星玉.md)、[盾玉](04-盾玉.md)、[骑玉](48-骑玉.md)、[界玉](24-界玉.md)。普通死亡、地面碰墙死亡、跳跃越界清理写入dead_last的行为并不完全相同；不能把任何对象消失都当成可复活尸体。

普通兵玉接[愈玉Heal](18-愈玉.md)，墙与核心接[缮玉Repair](17-缮玉.md)。范围以目标实际中心测试，多来源是OR而非按数量相加。生成物是否能回复或复活须看自己的实现，不能由unit列表成员身份推断。

## 墙体、加速器与核心

普通墙随车体平移，用墙形状提供接触与支撑；受创用中心±6四角，每次有效Atk扣1。多数墙HP耗尽后进入breaking，之后计数>4移除；repair不清除breaking。红/蓝加速器改用HP耗尽立即删除的路径，箱体有自己的下落和死亡逻辑；电梯壁另有上下移动。墙构造没有r参数，不能把其编码角度当成朝向或攻击时序控制。

红/蓝构造时分别贡献axl的1/2，正常死亡扣回；基础axl=1。Base每次xs+=axl/1000，碰撞、边界和反弹还会改速度。因此保持初始加速等级不保证瞬时速度或战中加速度相同。

核心使用独立全局HP和13点Atk检测；与普通兵玉的移动、计时和死亡规则分开。两个核心都接repair；[普通核心](core-0-要塞核心.md)没有主动攻击，[BOSS核心](core-1-BOSS要塞.md)另有激光。核心坐标影响默认seed，移动核心时不能把全部变化归因于几何。

## 攻击对象与更新顺序

fort=wall+unit；team=wall+unit+Shield+Atk。普通箭等弹体用弹心查询team，可能被剃玉攻击区触发；射线、激光、核弹各有自己的判定，不能把所有攻击统一看成“两个圆相碰”。受害兵玉/墙/核心直接查询Atk扣血，Shield不是一层对所有现存攻击区统一减伤的规则。

HitsDrop是短暂命中圆；HitsDropFrames按计数移除；HitsBomb的半径随更新变化；近战区、护壁、激光分别看来源页。普通Bullet的move先以当前速度移动并量化，再加重力，和兵玉jump先加重力不同。迎击标记gei_flg=2由各弹体后续处理，不等于立即无害删除。

元素按ID顺序更新，初始创建顺序由双方及阵码顺序决定。帧首冻结常规更新的ID上界，新生对象当帧不走常规step，但立即注册传感器；部分构造分支还会立即移动。晚更新对象可能当帧就看见新攻击或治疗。自身frame/cnt、有效递增次数、全局帧与目标真正看到的覆盖窗口必须分开。

## 使用边界

改阵记录单位页路径、适用引擎、当前职责、x/y/r影响与待测假设；同任务同版本可引用已有阅读记录，新增单位或改职责时补读。单位页中的用途是机制推导，不是胜率承诺；相同终局也不证明全部轨迹等价。用真实对局的事件、对象链、HP账本解释疑问，完整阵池评测判断强弱。

源码：[ball.rs](../../../../rust/vendor/gkt-core/src/engine/ball.rs)的step/land_inner/jump_inner/ground_inner；[mod.rs](../../../../rust/vendor/gkt-core/src/engine/mod.rs)的unit_make/main_setup/update/team_hit/atk_hit_4corner；[wall.rs](../../../../rust/vendor/gkt-core/src/engine/wall.rs)、[base.rs](../../../../rust/vendor/gkt-core/src/engine/base.rs)、[core.rs](../../../../rust/vendor/gkt-core/src/engine/core.rs)、[hits.rs](../../../../rust/vendor/gkt-core/src/engine/hits.rs)。

## 离散落体与条件支撑能力

源码机制：land_inner先增加竖直速度，只查询本步最终脚点(drop_y+15)，碰到实体才逐像素向上回推，并没有沿整段下降路径连续扫碰撞。核心外角等薄支撑区可能被加速落体跨过；因此竖直投影与实体相交，不等于实际必然停在上面。与之相反，1px横移也可能让下一步端点进入支撑区。依据[Ball::land_inner](../../../../rust/vendor/gkt-core/src/engine/ball.rs)和[Core::hit_test_point](../../../../rust/vendor/gkt-core/src/engine/core.rs)；具体布局用重力审核及端点对照确认。

依赖墙损坏后掉落的战术，先让带墙原布局稳定，再删除实际支撑对象继续执行重力，检查目标支撑对象、最终高度和收敛。不要只把终点画在车板上，或拿刚生成就删墙的结果代替所有触发路径。静态能力证明与真实受击后的跳跃、位移、击杀分别说明。
