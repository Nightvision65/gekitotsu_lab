# 箱玉（ID 44）

在面前生成可支撑、可修理的箱壁，动态改变平台与阻挡。

## 身份与适用范围

| 项目 | 固定值 |
|---|---|
| 编码ID / Rust类型 | 44 / `BallKind::Box` |
| 军资（工作台目录） | 70 |
| 战斗构造HP | 15 |
| 初始化speed | 200 |

依据Rust提交`149e365221b09330a72d9a6a1804605e3ce4e1f5`与当前`catalog-hp-v1`规则，版本选择见[规则版本](../../unit-hp-rules.md)。本文机制是源码结论；用途与微调建议是基于机制的待测方向，不代表单独胜率证明。军资/中文名来自工作台目录，HP与时序以Rust构造和分支为准。先读[共通规则](common.md)中的兵玉部分；[文档清单](coverage.json)保存单位条目与源码身份。

## 触发与节拍

初始化模200；cnt=200且非jump时检查出口，受阻则减回199；通过后cnt=204生成并归零。

speed>0时，普通工作台x的初始cnt为`-((x+16)%speed)`；这里的计时是有效递增次数，跳跃会暂停递增，受伤等可能改变状态。speed=0不套取模公式。

## 详细机制与生成对象

- 出口为本体沿r偏移38，检查本体圆或当前on_side的fort是否遮住该点；因此“204周期”只适用于出口一直可用。
- 箱体归属当前on_side的wall列表，HP15；生成于地面的箱体on_side=-1，其余随对应车体平移并以重力1下落，接触支撑上推，落到566转为地面箱。
- 箱壁可支撑兵玉，接repair而非heal；受到敌Atk四角判定扣HP，耗尽、己方hp0或y<-600时移除并生成短暂Wall残留体。
- 地面箱中心碰到敌wall会设HP0；箱体不是普通兵玉，不能由其死亡推断圣玉dead_last被更新。

## 受击、恢复与死亡

没有额外的受击重置分支；本体仍按共通规则扣血、治疗和死亡。

本体受击、支撑、跳跃、heal与死亡顺序见[共通规则](common.md)。独立生成物不自动随本体死亡消失；依附物是否清理由各自分支决定。

## 改阵与对手诊断

r与出口位置决定能否持续造箱；联合检查箱体堆积、落稳高度、突击落点和箱玉自身存活。不要把动态平台当成固定初始支撑。

发现对方带此单位时，同样检查它的支撑、保护、实际出手位置与生成对象；先选少量目标对局确认机制是否生效，再用完整评测判断改阵收益。
