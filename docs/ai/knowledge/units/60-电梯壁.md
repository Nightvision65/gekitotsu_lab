# 电梯壁（ID 60）

上下移动的平台，动态调整所支撑兵玉的高度与辅助关系。

## 身份与适用范围

| 项目 | 固定值 |
|---|---|
| 编码ID / Rust类型 | 60 / `WallKind::Elevator` |
| 军资（工作台目录） | 60 |
| 战斗构造HP | 75 |
| 初始化speed | 墙体专用，见触发规则 |

依据Rust提交`149e365221b09330a72d9a6a1804605e3ce4e1f5`与当前`catalog-hp-v1`规则，版本选择见[规则版本](../../unit-hp-rules.md)。本文机制是源码结论；用途与微调建议是基于机制的待测方向，不代表单独胜率证明。军资/中文名来自工作台目录，HP与时序以Rust构造和分支为准。先读[共通规则](common.md)中的墙体部分；[文档清单](coverage.json)保存单位条目与源码身份。

## 触发与节拍

初始ys=1；每次step_ex按阻挡情况保持或翻转±1，未阻挡时沿y移动1。

## 详细机制与生成对象

- catalog-hp-v1将Elevator显式构造为HP75、max_hp75，与工作台目录一致；原上游149e365走默认HP35。旧源码原件另存，未替换的JNI DLL不自动应用本修正。
- 随车体平移后，用当前位置下方(y+15)的fort及上方(y-48)的wall等条件决定反向；到base.y-380的上界也会反向。
- 用于自检时临时平移自身避免误碰，再恢复；实际平台不是始终停在初始y。兵玉按脚点支撑，能否随平台与落地状态需逐步检查。
- 普通墙受创、repair和breaking规则仍适用；没有独立攻击或方向性辅助传感器。

## 受击、恢复与死亡

沿用普通墙的受创、修理与破损路径。

修理读取Repair，具体破损、立即死亡或动态箱体分支按上文。

## 改阵与对手诊断

x/y决定行程中的碰撞、顶板与兵玉实际出手高度，r不参与构造。记录运动阶段和火力首发的对应关系；不能仅凭初始高度预测整局。

发现对方带此单位时，同样检查它的支撑、保护、实际出手位置与生成对象；先选少量目标对局确认机制是否生效，再用完整评测判断改阵收益。
